# 启星程校服官网 V4 设计规格

**日期：** 2026-10-16
**状态：** 已确认设计，待实施计划
**基线：** GitHub `main` 提交 `a7fbb79c7975f9d0e1b6b71997c5bed64037d75e` 的 V3 镜像
**实施范围：** 本地隔离分支 `codex/v4-campus-yearbook`；不发布、不修改远程 `main`

## 1. 目标与受众

V4 将现有长篇品牌画册改造成一个以真实校服为主角、同时服务两类用户的静态官网：

1. 学生家长能按夏装、秋装、冬装找到产品，查看整套与单件照片、真实细节、对应尺码表，并通过电话或微信咨询。
2. 学校采购人员能了解已确认的生产经验、面料与工艺信息、可沟通的批量定制流程，并使用真实联系方式发起咨询。

成功标准：页面在 375、768、1440 像素宽度下清晰可用；产品和尺码信息不混用；图片不拉伸、不伪造；联系方式真实；没有价格、库存、付款或虚假表单成功状态；最终仅提供本地预览。

## 3. 技术架构

采用无构建依赖的静态多页面结构，兼容 GitHub Pages：

```text
index.html                         首页
products/
  summer.html                     夏装详情与夏装尺码表
  autumn.html                     秋装详情与秋装尺码表
  winter.html                     冲锋衣详情与冬装尺码表
assets/
  css/site.css                    全站设计令牌、布局、组件、响应式与 reduced-motion
  js/site.js                      导航、移动菜单、灯箱、联系方式弹层、焦点管理
  js/product-gallery.js           产品图库和缩略图切换
  media/                          优化后的响应式图片
tests/
  content-check.mjs               文案、链接、图片与尺码数据静态检查
  browser-check.mjs               Chromium 响应式和交互验收
docs/
  content-confirmation.md         未确认信息和数据来源清单
```

页面不迁移到 React，不引入 Framer Motion。现有技术只需要原生 HTML、CSS 和 JavaScript；动效通过 CSS 过渡和少量原生脚本实现。

## 4. 视觉系统

### 4.1 概念

主题为“校园青春画册”。首页使用不等宽图文构图、真实产品留白和少量大幅校园人物图，避免统一圆角卡片、装饰渐变、连续阴影、无意义英文眉题和装饰编号。

唯一重点视觉是首屏校园人物图与留白品牌语；其他区域保持克制，让真实产品照片承担主要视觉信息。

### 4.2 色彩令牌

- `--color-primary: #163653`：导航、标题、主要按钮。
- `--color-accent: #23745B`：学校定制、少量强调。
- `--color-surface: #FFFFFF`：主要背景。
- `--color-surface-soft: #EAF3F8`：分区背景。
- `--color-text: #273641`：正文。
- `--color-text-muted: #596873`：辅助文字。
- `--color-border: #CBD9E2`：表格、分隔线和控件边界。
- `--color-focus: #0B74B8`：键盘焦点，需与相邻背景保持清晰对比。

### 4.3 字体与排版

- 字体栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`。
- 不请求外部字体。
- 手机正文最小 16px，正文行高 1.7–1.8。
- 桌面正文行宽控制在约 60–75 个中文字符，移动端约 35–60 个字符。
- 标题使用黑体系统，通过字号、字重和留白建立层级，不用斜体单词或彩色单词制造装饰。

### 4.4 布局与节奏

- 采用 4/8 像素间距系统。
- 内容最大宽度约 1280px；桌面左右留白不低于 32px，手机约 20px。
- 桌面首屏为左侧文案、右侧人物图；手机为文案在上、重新定位的人物图在下。
- 产品图使用 `object-fit: contain`，不裁掉衣领、袖口、裤脚。
- 校园人物图允许裁切，但为手机和桌面设置不同 `object-position`。

## 5. 全站导航与联系入口

### 5.1 桌面导航

Logo、校服系列、品质工艺、学校定制、关于我们、联系我们。首页锚点和三个产品详情页之间的导航位置保持一致。

- 44–48px 以上的菜单按钮和关闭按钮。
- 打开后显示同一组中文导航；不依赖悬停。
- 设置 `aria-expanded`、`aria-controls`，Escape 可关闭，关闭后焦点回到触发按钮。

### 5.3 联系入口

- 电话按钮使用 `href="tel:18664724586"`。
- 微信按钮打开可关闭、可键盘操作的二维码弹层。
- 弹层说明：“同机使用时可保存或截图二维码，再用微信识别；不会自动打开加好友。”
- 手机底部固定栏只有“电话咨询”和“微信二维码”，使用 `env(safe-area-inset-bottom)` 并为正文预留等高空间。
- 不提供会让用户误以为请求已发送到服务器的表单。

## 9. 图片处理与文件策略

### 9.1 原图保护

- RAR 原件继续保留在用户提供路径，不改写。
- 解压原图保留在本地 `source-materials/unpacked/`，由 `.gitignore` 排除，不将约 160 MB 原始图片直接加入网站版本。
- 现有 24 个 SVG 继续保留，以确保 V3 可恢复；V4 新页面使用提取和优化后的位图副本。

### 9.2 响应式副本

- 校园横图：WebP 约 768/1280/1600 宽；维持人物和服装，允许按不同断点调整裁切位置。
- 竖版海报：WebP 约 640/1024 宽；灯箱使用较大版本并保持原比例。
- 产品完整图：含透明通道的 WebP，约 480/960/1600 宽；不裁切衣领、袖口、裤脚。
- 产品细节图：约 480/960/1440 宽；不生成不存在的纹理。
- Logo：从 `image-03.svg` 的内嵌 PNG 提取透明副本，保持比例；不得重绘。
- 尺码图和二维码：保留原始附件副本；网页预览可生成无明显文字损失的优化版，但原图放大链接始终指向清晰原图。

每个 `<img>` 设置明确的 `width`、`height` 或 `aspect-ratio`，首屏图使用 `fetchpriority="high"`，其他图片使用 `loading="lazy"` 和合适的 `srcset`/`sizes`。

## 10. 交互与无障碍
